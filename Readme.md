 # Техническое задание

 ## Онлайн-платформа обучения музыке и другим видам искусства

 **Версия:** 1.0\
 **Тип проекта:** образовательная онлайн-платформа\
 **Формат:** Web Application\
 **Основные пользователи:** ученики, преподаватели, администраторы

---

 # 1\. Описание проекта

 Необходимо разработать современную онлайн-платформу для обучения музыке и другим видам искусства.

 Платформа должна объединять учеников и преподавателей и предоставлять возможность проходить онлайн-курсы, смотреть видеоуроки, выполнять практические задания, загружать результаты своей работы и получать обратную связь от преподавателей.

 Основная концепция:

 > **Ученик выбирает направление → выбирает курс → оплачивает → проходит уроки → выполняет задания → получает проверку преподавателя → отслеживает прогресс → завершает курс и получает сертификат.**

 Платформа должна быть рассчитана как на самостоятельное обучение, так и на индивидуальные/групповые занятия с преподавателем.

---

 # 2\. Основные направления обучения

 На первом этапе платформа должна поддерживать следующие категории:

 ### Музыка

- Вокал
- Гитара
- Фортепиано
- Скрипка
- Барабаны
- Музыкальная теория
- Сольфеджио
- Композиция
- Аранжировка
- Музыкальное продюсирование

 ### Изобразительное искусство

- Рисование
- Живопись
- Иллюстрация
- Digital Art
- Графический дизайн
- Анимация

 ### Другие направления

 Архитектура платформы должна позволять добавлять новые категории без изменения основной структуры системы.

---

 # 3\. Цели платформы

 Основные цели:

 - предоставить качественное онлайн-обучение;
- объединить преподавателей и учеников;
- продавать образовательные курсы;
- предоставить преподавателям инструменты для создания курсов;
- обеспечить контроль прогресса учеников;
- обеспечить обратную связь;
- создать возможность индивидуальных занятий;
- сформировать единую образовательную экосистему.

- создать профиль;
- выбрать курс;

- загружать домашние работы;
- получать комментарии преподавателя;
- отслеживать прогресс;

- бронировать индивидуальные занятия;
- получать сертификаты.

```
┌─────────────────────────────────────┐
│ Курс: Основы игры на гитаре         │
```

 # 10\. Домашние задания

 Особенно важная часть платформы.

 Пример:

 **Задание:**

 > Запишите исполнение гаммы и загрузите аудио.

 Ученик:

 1. выполняет задание;
2. загружает файл;
3. отправляет преподавателю;
4. ожидает проверки.

 Преподаватель:

 1. получает уведомление;
2. открывает работу;
3. прослушивает/просматривает файл;
4. оставляет комментарий;
5. ставит оценку;
6. отправляет результат ученику.

 # 17\. Создание курса

 Преподаватель должен иметь пошаговый редактор.

```
Шаг 1 — Основная информация
Шаг 2 — Программа
Шаг 3 — Уроки
Шаг 4 — Материалы
Шаг 5 — Задания
Шаг 6 — Цена
Шаг 7 — Предпросмотр
Шаг 8 — Отправить на модерацию
```

 После публикации курс становится доступен ученикам только после одобрения администратора, если такая модерация включена.

 # 18\. Платежи

 Система должна поддерживать:

 - покупку курса;
- индивидуальные занятия;
- подписку;
- промокоды;
- скидки;
- возвраты.

 Каждая транзакция должна сохраняться в базе.

```
Payment
 ├── User
 ├── Product
 ├── Amount
 ├── Currency
 ├── Status
 ├── Payment Provider
 └── Created At
```

 Конкретный платежный провайдер выбирается отдельно в зависимости от страны запуска проекта.

 # 45\. Критерии готовности MVP

 MVP считается готовым, когда пользователь может:

 1. зарегистрироваться;
2. войти в аккаунт;
3. найти курс;
4. открыть страницу курса;

6. получить доступ;
7. посмотреть урок;

10. получить проверку преподавателя;

 Преподаватель должен иметь возможность:

 1. зарегистрироваться;

5. добавить задания;

 Администратор должен иметь возможность:

 1. управлять пользователями;
2. управлять преподавателями;
3. модерировать курсы;
4. управлять платежами;
5. управлять контентом;

 # 48\. Главный принцип продукта

 Платформа должна строиться не вокруг простого просмотра видео, а вокруг **полного цикла обучения**:

 > **Learn → Practice → Submit → Feedback → Improve → Complete**

 То есть:

 **Изучил → Практиковался → Отправил работу → Получил обратную связь → Исправил → Продолжил обучение.**

 Именно эта система должна быть ядром платформы.

 Этот документ уже можно использовать как основу **README для GitHub или ТЗ для команды разработки**. Если проект планируется реально запускать, следующим этапом я бы отдельно сделал **архитектуру базы данных (ERD), полный список API и подробную структуру каждой страницы**, чтобы разработчик мог практически сразу начинать работу.
